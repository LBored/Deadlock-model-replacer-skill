# 案例：Deadlock 若叶睦替换格瑞墓

此文档记录一次实际项目的证据和故障结果，帮助诊断相似问题。它不是默认配置。开始新项目时必须重新确认游戏版本、资源路径、工具能力和用户授权，不能直接复用这里的数值或文件名。

## 项目范围与工具快照

- 目标为 Deadlock 的格瑞墓，项目检查时内部名为 `necro`，主模型位于 `models/heroes_wip/necro/necro.vmdl_c`。
- 制作阶段使用 Blender 5.2.1、Reduced CSDK 12、SourceIO、Blender Source 2 Tools、Source 2 Viewer/ValveResourceFormat 和 VPKEdit 4.4.2。
- 模型导出采用 DMX Binary 9 / Model 22，普通蒙皮限制为每顶点最多 4 个有效影响；布料专用属性不参与普通权重清理。
- 具体工具版本只说明当时通过了哪些链路，不代表后续 Deadlock 构建仍兼容。

## 模型、布料与道具

替换模型保留了目标游戏骨架、动画依赖、挂点和技能逻辑。裙子经历了腿部支撑、后裙解绑、代理约束和局部间距多轮调整：完全解绑后裙改善了随腿踢动，却在行走、跳跃和滑铲中造成严重穿插；加入低幅、连续的腿部支撑更可控。增加内衬只能减少部分可见内部，未解决前进动作中的网格折叠，因此不能把遮挡面当作拓扑或权重修复。

一技能罐子原先嵌在原人物网格中。只保留骨骼和挂点会使它消失，最终需将对应面组独立保留，并验证 bodygroup、LOD 与权重。

布料代理使用过球体和胶囊碰撞体，并从编译成品的物理数据中回读节点、约束与刚体。项目所用工具对游戏内地面碰撞支持有限；界面存在该选项并不等于运行时生效。

## 材质兼容

该 CSDK 的 pbr 路径使用了 `TextureTranslucency1` 和 `g_flAlphaTestReference1`。相似但错误的参数名曾导致眼睛、衣领和胸口区域显示异常。修复时使用线性 Alpha 图、清理遮挡/重复面，并确认资源编译缓存已刷新。这两个参数名只属于本次 shader 模板。

## 死亡状态散架

候选模型的正常动画全部可用，但进入死亡状态后刚体散开。对比发现原模型有 18 个关节，而旧编译产物的 `PHYS.m_joints` 为空。修复按刚体语义名称重映射关节端点，保留局部框架、角度限制、阻尼和碰撞开关；游戏内死亡、尸体停留和复活验证通过。18 是该角色当时的事实，不能作为其他模型的断言。

## 语音替换

资源发现阶段核对到 1,821 个目标角色声音资源，约 42.6 分钟，源音为 44.1 kHz 单声道。声音容器为 Version 5，带 `CTRL` 与 `CVoiceContainerDefault`。项目使用社区 TogetsuDo 若叶睦 RVC v2 40k 模型和 RVC Project 离线推理；试听比较 0、+2、+4 半音后，用户选择所有类型使用 0 半音，首轮采用 RMVPE、检索比例 0.75、protect 0.33。

这些数值来自一次试听决定。批量处理仍以源音、模型、索引、推理版本和参数哈希作为缓存键，并逐条检查时长、静音、削波、截断和错配。重建容器时保留事件映射、采样数、循环和音素语义，按转换 PCM 重建原有包络。

## 封包发现

VPKEdit 4.4.2 在该项目的一次大条目封包中产生错误的分块 MD5。问题由独立校验复现后，只重建受影响的 archive MD5 记录及关联摘要，并由 VPKEdit 与 Viewer CLI 双重校验。这个后处理只适用于重现同一缺陷的包，不能作为所有 VPK 的固定步骤。

## 可迁移结论

- 正常动画通过不能证明死亡关节存在；死亡和复活必须单独验收。
- 衣物穿模要在拓扑、蒙皮、代理约束和运行时碰撞之间定位，内衬只能作为有限遮挡。
- 原人物网格可能携带技能道具，删除身体面组前应按部件、bodygroup 和 LOD 审计。
- UI 与声音应从已接受模型包增量合并，并证明基线资源逐文件不变。
- 案例没有附带游戏资源、人物模型、图片、声音权重或 SDK；这些内容的权利与许可独立于技能包的 MIT License。
