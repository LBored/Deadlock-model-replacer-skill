# Deadlock / Source 2 专项

以下规则用于 Source 2 项目；不同游戏、构建和工具版本必须重新探测。不要硬编码角色路径、骨骼数、节点数或文件长度。

## 工具能力

- [Source 2 Viewer / ValveResourceFormat](https://s2v.app/)：列包、提取、资源块解析、独立导出与校验。其 [格式支持说明](https://s2v.app/ValveResourceFormat/guides/format-support.html) 区分原生反编译与 glTF 等中间格式，说明布料与布娃娃关节不能依赖反编译完整恢复。
- [SourceIO](https://github.com/REDxEYE/SourceIO)：Blender 导入及资源格式研究；核对安装版本实际支持的格式。
- Blender Source 2 导出插件：确认具备所需 DMX 和布料属性导出能力；名字相近的 Source 导出器不保证功能等价。读取本机插件源码/操作符和维护者说明，锁定提交。
- 游戏匹配的 ModelDoc/资源编译器：先验证工具版本与当前游戏资源版本兼容。缺失工具从合法可用的发行渠道取得，不随技能附送 SDK 二进制。
- [VPKEdit](https://github.com/craftablescience/VPKEdit)：本地封包和校验；下载在维护者 [Releases](https://github.com/craftablescience/VPKEdit/releases)。

## 提取和编辑

先用当前包确认模型、材质、骨架、动画图及依赖。内部名和资源路径必须从当前游戏包、事件表或依赖关系中发现。

保留原编译二进制，另导出可编辑 `.vmdl`/DMX 或 glTF。glTF 适合看网格和权重，不能替代原生 cloth、bodygroups、全部 LOD 和动画图引用。不要把 Viewer 中一个可播放片段当作完整游戏动画。

从插件能力和目标编译器共同确定 DMX 版本。导出前后确认 skin weights 和 cloth 属性真实保留。原始骨架子集按名字检查父子和 rest 矩阵；普通蒙皮影响上限从目标格式读取，物理组不参与普通权重清理。避免重复缩放；导出器执行撤销或重建对象后重新获取对象引用。

## ModelDoc 布料

在 ClothProxyMeshList 中选择当前工具支持的碰撞形状。对球体或胶囊体核查 `parent_bone`、球心/半径或端点/独立半径、布料碰撞开关和碰撞层。转换至骨局部空间后编译；从成品物理块回读刚体、节点和约束是否与作者数据对应。字段名与位置以当前解析结果为准，不写固定二进制偏移。

普通 ragdoll/hitbox 形状不是布料碰撞的证明。工具界面存在某个碰撞选项也不能证明目标游戏运行时实现了该能力，必须以游戏测试确认。

## 动画、关节和材质兼容

旧编译链曾丢失 `DATA.m_animGraph2Refs`、`m_vecNmSkeletonRefs` 及所需 RERL 外部依赖。比对当前原模型并在兼容时恢复完整引用；不能仅保留少数测试动作。若编译器不认识某些 ModelDoc 节点，只在临时编译输入适配，完整源数据保留，并验证编译后补回的语义。

死亡散架且普通动画正常时，应检查 `PHYS.m_joints` 等关节数据；参见物理参考按刚体名字映射。编译后骨索引会变化，因此不能直接复制数值索引或盲目复用整个 PHYS。

材质参数名必须从当前 shader 定义或成功模板读取，名字相近不表示语义相同。透明和裁切材质应使用正确色彩空间的 Alpha 输入，并验证编译缓存确实刷新。

## 二进制修补与封包

优先原生编译和成熟解析库。必要的后处理要先识别资源头、版本、块目录、压缩和带类型 KV3；保存原字节，重算所有受影响偏移和长度，回读后逐字段验证。重复命名块应按出现顺序保留；不能用只按四字符标签的字典覆盖重复网格块。

若封包器对大条目生成错误的分块摘要，应先用独立工具复现并定位，再切换版本或使用经过验证的写入器修复；不要预先对所有 VPK 执行二进制补丁。任何修复都须保留树和资源 payload，只重建被证明错误的摘要，并由两套独立工具校验。

命令选项先检查本机版本，不能从其他版本的帮助文本猜测。技能自带脚本只验证 CRC 和 payload 哈希，不能替代封包器或 Viewer 的包级校验。

若添加 UI/声音，另读 [ui-and-voice.md](ui-and-voice.md)。声音 v5 CTRL 的头长度不等于音频总文件长度；不要套用模型容器的长度不变量。
