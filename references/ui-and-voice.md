# 可选头像和语音扩展

仅当用户明确要求时使用。已接受模型包为不可变基线；UI/声音完成后合并，原模型、材质、物理 payload 逐文件一致。不会因为扩展功能而自动重编译模型。

## 头像与选角图

定位实际 UI 图片、状态变体、材质/图集和显示遮罩；不要凭角色名构造路径。普通/濒死/连杀的映射应逐项记录。对用户提供图片精确裁剪、等比缩放，保留所需头顶、双眼、嘴和下巴；同组对齐头部占比与眼高，预览原尺寸及实际 HUD 大小。不烘入游戏自身圆框、背景与状态标记。

从当前原纹理确认尺寸、通道、压缩、mip、Alpha、方向及色彩空间。缩小透明图先正确处理预乘 Alpha 再还原，避免黑边。优先匹配的原生编译工具；无压缩模板替换仅适用于已解析明白的格式，保持合法头与 mip 布局。反向解码所有 mip 并逐像素/容差比较。

## 语音

先按事件表与目标角色目录交叉确认完整资源集合；本人语音与技能/武器 SFX、其他角色分开。记录事件名、路径、源哈希、编码、采样率、声道、样本数、时长、循环、音素和包络。解码样本数以容器定义核对；有损编码延迟不能凭文件时长猜。

用户请求变声时才下载/使用其选定或经过试听选择的模型。记录发布者、来源、版本、权重与索引哈希，使用独立推理环境。先准备覆盖短/长台词、标记、喊叫、疼痛、死亡和喘气的样本对照，并先验证小声音包能被游戏正常触发与结束。已有相同链路和配置的明确认可无需再次询问。

变声引擎、音高、特征提取器、检索比例和辅音保护必须通过覆盖不同语气的试听冻结，不能从另一角色或歌声模型复制参数。歌声模型是否适合台词要靠试听。

批处理以源 SHA、模型/索引 SHA、推理版本和参数生成缓存键，每条输出哈希及状态单独记录；参数改变只失效相关产物。保留原音和无损输出。时间对齐检查活跃边界，只有静音可补齐/裁短；有声音被截断时单条重做或补上下文重推理，不能直接硬裁伪造长度一致。按原音分别校准响度并限制削波，保留轻声/大喊相对强弱，不默认统一压响或加混响。

## Source 2 声音容器注意点

先探测声音资源版本、控制块类型和容器类。确认音频 payload 起点和头部长度；声明头长度可小于总文件长度。用带类型 KV3 解析保留字段类型和结构，不套用模型资源头长度规则。

改为 PCM16 时更新格式、streaming 字节数及实际音频，保留 rate、channels、sample count、duration、event path、loop 和已有音素语义。按该资源原 envelope analyzer 的采样窗口、阈值和曲线时刻从转换 PCM 重建 RMS 包络及相应斜率；不是统一给所有格式插入 50 ms 包络。原无音素时不制造口型数据。

先用少量原音重建新编码容器，回读字段和 PCM，并由独立工具解码，再游戏验证。当前已接受编码可以扩大生产。原非音频块除必要字段外保持；容器已改变时重新检查所有偏移和长度。

全量校验无遗漏/错配、采样数精确、非有限值/静音异常/削波/边界截断和音量偏差。自动信号检查不能证明每句自然或吐字正确。失败项单独修复，不以原音静默回填假装全部变声成功。

交付独立语音包和完整整合包时分别验证资源范围；完整包中的基线资源全部不变。安装选“旧模型包+独立语音”或“完整包”一种，停用试听包。游戏复测对话、标记、受击、死亡、复活和连续触发。
